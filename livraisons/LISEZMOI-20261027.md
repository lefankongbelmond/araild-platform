# MX-CONNECT — mise à jour du 27/10/2026 (`mxconnect-maj-20261027.zip`)

Version : **2026.10.27**.

Ce ZIP est **cumulatif** : il contient tout le Lot 3 du 26/10 (projets, emplois et opportunités, « Je m'engage », « Soutenir ou devenir partenaire », candidatures), plus le correctif ci-dessous. Le détail du Lot 3 se trouve dans `LISEZMOI-20261026.md`.

Il n'est **pas nécessaire** d'installer d'abord le ZIP du 26/10.

## 1. Le problème

Après l'installation du 26/10, certains navigateurs continuaient à afficher l'ancienne mise en forme.

La cause : le service worker du réseau (`sw-social.js`) garde en mémoire la feuille de style. Il ignorait son numéro de version, et son propre nom de cache n'avait pas changé. Tout navigateur qui avait déjà visité le site recevait donc **l'ancien** `mx-social.css`, même après la mise à jour.

## 2. Ce qui change

- `sw-social.js` :
  - nouveau nom de cache (`mx-social-2026.10.27`) : l'ancien cache est supprimé automatiquement ;
  - les fichiers CSS et JS sont désormais rangés **avec** leur numéro de version (`?v=`). Une nouvelle version est donc toujours téléchargée.
- `mxconnect/VERSION` passe à 2026.10.27 : la 1re visite relance la mise à jour (caches vidés, migrations appliquées).

## 3. Installer

1. **Sauvegarde** : base centrale et dossier `htdocs/mconnect`.
2. Extraire le ZIP **directement dans `htdocs/mconnect`**, en remplaçant les fichiers, y compris `index.php`, `.htaccess` et `sw-social.js`.
   - ⚠ Le gestionnaire de fichiers LWS crée souvent un sous-dossier portant le nom du ZIP (`mxconnect-maj-20261027/`). Dans ce cas, il faut déplacer **son contenu** dans `htdocs/mconnect`.
   - Ne pas toucher au `.env`, ni à `mxconnect/vendor/`, ni à `mxconnect/storage/`.
3. Ouvrir https://m.araild.com une fois.

## 4. Si « rien n'a changé » : 4 contrôles

1. **Le bon dossier.** Dans le gestionnaire de fichiers, ouvrir `htdocs/mconnect/mxconnect/VERSION` : il doit contenir `2026.10.27`.
   - S'il contient encore `2026.10.21` ou `2026.10.26`, les fichiers ne sont pas au bon endroit. Cherchez un sous-dossier `mxconnect-maj-…` créé à l'extraction.
2. **L'adresse directe.** Ouvrir https://m.araild.com/opportunites.
   - Si la page « Emplois et opportunités » s'affiche, la mise à jour est en place. Elle est vide tant que personne n'a publié d'offre, c'est normal.
   - Si vous obtenez « Page introuvable », le code n'est pas déployé : voir le contrôle 1.
3. **Le back-office.** Dans l'espace d'une mutuelle, le bas de page affiche « Version 2026.10.27 », et le menu Réseau social contient « Projets et opportunités ».
4. **Le navigateur.** Recharger avec Ctrl + F5. Sur téléphone, les nouvelles rubriques « Projets et résultats » et « Emplois et opportunités » sont dans le menu **☰**, pas dans la barre d'icônes.

Si le contrôle 2 renvoie une erreur 500 : `/_installation?token=…` → « Appliquer la mise à jour », puis envoyer le texte des « 6 dernières erreurs ».

## 5. Tests réalisés (copie fidèle LWS : Apache, PHP 8.4, MariaDB 11.8)

- **Reproduction du défaut en navigateur réel.**
  - Avec l'ancien service worker et l'ancien CSS en cache, la page recevait l'ancienne feuille de style, même avec `?v=2026.10.26`.
  - Après dépôt du nouveau `sw-social.js` : l'ancien cache est supprimé et les styles du Lot 3 sont appliqués.
- **Pest** : 20 tests sur 20.
- **Navigateur, à 320, 360, 768 et 1366 px** : 113 pages sur 113 sans erreur JS ni défilement horizontal.
- **Mise en cache de production** (`optimize`, lancé par « Appliquer la mise à jour ») : réussie avec les nouvelles routes.
