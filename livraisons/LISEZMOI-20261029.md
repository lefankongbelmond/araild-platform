# MX-CONNECT — mise à jour du 29/10/2026 (`mxconnect-maj-20261029.zip`)

Version : **2026.10.29**.

ZIP **cumulatif** : Lot 3 (26/10), correctif du cache (27/10), design Lot 2 (28/10) et ce Lot 5. Il suffit d'installer celui-ci.

## 1. Le besoin

Deux pistes de la feuille de route :
- les **documents PDF dans les publications** : le type « Document public » existait déjà, mais sans possibilité de joindre un fichier ;
- les **sondages**, prévus au Lot 2 mais jamais réalisés.

## 2. Ce qui change

### Documents PDF publics

- **Dans une publication faite au nom d'une page** (mutuelle ou page de membre) :
  - ouvrir la zone de publication, puis la section « **Document PDF** » ;
  - 3 documents maximum, 10 Mo chacun ;
  - la publication devient automatiquement « Document public ».
- **Dans le back-office d'une mutuelle** : Réseau social → Nouvelle publication → « Documents PDF publics ».
- **Dans un projet** : section « **Documents du projet** » du formulaire, sur le réseau comme dans le back-office.
  - On y dépose rapports d'activité, comptes rendus ou affiches : 10 par projet, avec un titre.
  - Ils apparaissent sur la page du projet, bloc « Documents ».
  - Ils aident l'administration du réseau à **vérifier les résultats déclarés**.
- **Protections** :
  - **seuls de vrais PDF** sont acceptés : le contenu du fichier est contrôlé, pas seulement son extension ;
  - case obligatoire « Ces documents sont publics et ne contiennent aucune donnée médicale ou personnelle » ;
  - **jamais sur un profil personnel** : les documents sont réservés aux pages ;
  - le fichier est **téléchargé**, jamais ouvert dans le site. Il est isolé du site (en-tête de sécurité « sandbox ») et n'est pas accessible par `/media` ;
  - un document suit la visibilité de sa publication ou de son projet : une publication supprimée ou un projet en brouillon rend le document introuvable pour le public ;
  - supprimer une publication, un projet ou une page **efface aussi les fichiers**.
- **Suivi** : un compteur de téléchargements est visible par les gestionnaires dans le formulaire du projet.

### Sondages

- **Créer** : ouvrir la zone de publication, puis « **Sondage** ».
  - Le texte de la publication sert de question.
  - 2 à 4 choix ; les choix vides ou en double sont retirés.
  - Durée : 1 jour, 3 jours, 1 semaine ou 1 mois.
  - Fonctionne pour tout membre et pour les pages.
- **Voter** : **un vote par personne**, modifiable tant que le sondage est ouvert (« Changer mon vote »).
- **Résultats** :
  - en pourcentages et en nombre de votes, **anonymes** : personne ne voit qui a voté quoi ;
  - visibles après avoir voté, une fois le sondage terminé, ou par les visiteurs non connectés (invités à se connecter pour voter).
- **Clôture** : un sondage terminé n'accepte plus de vote.

### Technique

- Migration **additive** `2026_10_29_000100_social_documents_and_polls` : 4 nouvelles tables (`social_documents`, `social_polls`, `social_poll_options`, `social_poll_votes`). Aucune table existante modifiée ; bases des mutuelles non touchées.
- Taille maximale d'un PDF réglable : `MXCONNECT_DOCUMENT_MAX_KB` dans le `.env` (10 240 par défaut).
- Service worker 2026.10.29 : la nouvelle mise en forme est chargée automatiquement.
- `/_installation` affiche un nouveau contrôle, « Envoi de fichiers (documents PDF) ». Il vérifie que `upload_max_filesize` et `post_max_size` permettent des PDF de 10 Mo.

## 3. Installer

1. **Sauvegarde** : base centrale et dossier `htdocs/mconnect`.
2. Extraire le ZIP **directement dans `htdocs/mconnect`**, en remplaçant les fichiers.
   - Si un sous-dossier `mxconnect-maj-20261029/` est créé, déplacer son contenu.
   - Ne pas toucher au `.env`, ni à `vendor/`, ni à `storage/`.
3. Ouvrir https://m.araild.com une fois : la migration s'applique d'elle-même.

## 4. Vérifier (5 minutes)

- [ ] `mxconnect/VERSION` contient `2026.10.29`.
- [ ] Fil → zone de publication : les boutons « Sondage » et « Document PDF » apparaissent quand on écrit. « Document PDF » n'apparaît que si vous gérez une page.
- [ ] Publier un sondage à 2 choix ; voter avec un autre compte : le pourcentage s'affiche.
- [ ] Sur la page d'une organisation que vous gérez : publier un petit PDF, puis le télécharger.
- [ ] Formulaire d'un projet → « Documents du projet » : ajouter un PDF ; il apparaît sur la page du projet.

## 5. Revenir en arrière

- Ré-extraire `mxconnect-maj-20261028.zip`.
- Les nouvelles tables restent en base, inutilisées.

## 6. Non inclus

- Pas d'**aperçu des PDF** dans le site (ouverture « en ligne ») : choix de sécurité, le document est téléchargé.
- Pas de **sondages depuis le back-office** des mutuelles : les mutuelles peuvent en publier sur le réseau via leurs gestionnaires de page.
- Pas de **modification des documents** d'une publication existante : il faut supprimer la publication et la refaire.
- Pas de documents dans les **groupes**.

## 7. Tests réalisés (copie fidèle LWS : Apache, PHP 8.4, fonctions système désactivées, MariaDB 11.8)

- **Pest : 36 tests, 260 vérifications, tous verts** (28 précédents + 8 nouveaux). Les nouveaux couvrent :
  - PDF joint au nom d'une page, téléchargement forcé avec `sandbox` et compteur, refus via `/media` ;
  - refus sur un profil personnel, d'un faux PDF et sans la case « publics », sans publication à moitié ;
  - publication supprimée → fichier effacé et document introuvable ;
  - documents de projet, brouillon privé puis public, suppression ;
  - projet supprimé → fichiers effacés ;
  - sondage : choix vides et doublons retirés, vote unique modifiable, totaux exacts, anonymat ;
  - refus à 1 choix et après clôture ;
  - visiteur non connecté.
- **Navigateur réel**, par la vraie zone de publication (JavaScript) :
  1. Sondage créé sur téléphone (360 px).
  2. Vote sur ordinateur, 100 % affiché.
  3. Changement de vote proposé.
  4. PDF publié au nom d'une page (768 px), puis téléchargé.
- **Non-régression navigateur** : 137 pages sur 137 sans erreur JavaScript ni défilement horizontal, à 320, 360, 768 et 1366 px.
- **Mise à jour réelle** : en changeant `VERSION`, la 1re visite applique la migration. La mise en cache de production (`optimize`) passe.

### Non vérifiable

- Le site réel m.araild.com n'est pas joignable depuis l'environnement de travail.
- La limite d'envoi de fichiers de PHP chez LWS (`upload_max_filesize`) doit dépasser 10 Mo pour les plus gros PDF. Sinon, l'envoi échoue avec le message « Fichiers trop lourds ». Le nouveau contrôle de `/_installation` l'indique ; à augmenter dans le panneau LWS (Configuration PHP) si besoin.
